# Debian 13 配布ペア：方式B（外部事前導入）の所有者決定

決定日：2026-11-18 / 状態：**設計採用、実装・実機受入は未完了**  
正本：[P25安定基礎設計憲章 v1.4 §6/§8A](../P25-FOUNDATION-POLICY.ja.md)  
関連：[初回SSH決定記録](CUNIT-FIRSTBOOT-SSH-OPENWRT-STYLE-20261118.ja.md)

## 決定

**インストールは外から、起動はP25、Debian本体はP44。**

OpenWrtのP25/P26互換ペアに対応し、Debianでは**署名済みP25のイメージと `P44-install.zip` を互換性が検証された配布ペア**とする。ただし「インストーラをP25/initramfsで実行する」方式Aは採用しない。

1. **専用の「外部インストーラ」「導入ツール」は作らない。** 所有者が承認したCodexの対話作業、または人間の手作業で、**Debian slot Aを起動する前に**、純正slot Bまたは検証済み復旧環境からP25（boot_a、32MiB）とP44 ext4（rootfs_data）を正確に識別する。
2. 署名済みP25のサイズ・SHA・書込対象PARTNAMEと所有者の**対象イメージ・実機操作に対する個別承認**を照合したうえで、既存の`dd`等によりboot_aだけへ書き込み、全量読戻しで確認する。P26および純正slot Bを保護する。
3. `P44-install.zip` は配布用の容器。手作業またはCodexがマニフェストとハッシュを確認し、既存Linuxの`mount`、`tar`等でDebian rootfsの`tar.zst`と対応カーネルモジュールを**外部環境から**P44 ext4へ配置する。uid/gid、モード、リンク、必要な拡張属性などを保全する。`P44-install.zip`をP44へ`dd`したり、ZIPをrootfsに直接展開したりしない。
4. P44は初回に空であることを確認し、既存ファイル・ユーザーデータ・設定・ホスト鍵があれば無断で上書きしない。途中失敗時はRunbookに従ってCodexまたは人間が**現物の状態を再確認してから**復旧し、盲目的な再展開をしない。P25とP44の実物SHA/互換性・読戻し確認後、別途許可を得てslot Aを起動する。
5. 初回起動時は**P44内のDebian 13**が動き、直結・隔離有線LANの`192.168.1.1/24`、TCP/22から`ssh root@192.168.1.1`で**パスワードとユーザー鍵なしの初回アクセス**を受け付ける（現時点では未実装）。SSHホスト鍵は各端末で初回生成しP44に永続化する。
6. ユーザーは**Debian上**で`passwd root`または`authorized_keys`登録を行う。個別認証で再接続できることを確認して初回無認証SSHを閉鎖し、再起動後も復活させない。
7. P44が空・破損しているならP25はDebianを起動できない。initramfsへインストーラや無認証rootサーバーを搭載して自動導入する義務はない。UARTエラーと必要なら**個別認証済み**救援経路を保持し、純正B・外部ツールからP44を復旧する。P44障害を無認証root SSH復活の理由にしない。

## 方式Aとの差と選定理由

旧設計の方式Aは「P25だけ書込み→initramfsの無認証SSHでZIP搬入→P44に展開→Debian起動」であり、P25にデータ転送・インストール・再試行・初期設定機構まで要求する。

**方式B**は、もともと外部環境からCodexまたは人間がP25とP44を準備する利用実態に合わせる。P25を最小の起動・診断・復旧基盤に保ち、専用インストーラ開発という新しい成果物を増やさず、**既存Linuxコマンドと手順書だけを使用する**。これは認証・安全の原則変更ではなく、**P44を準備する場所と実行順序、および導入作業の実施者の明確化**である。

「SSH rootが初回に無認証で入れる」という所有者決定は維持。ただし、その接続先は**P25のinitramfsではなく、あらかじめインストールしたDebian P44上の初期設定用SSH**へ変更する。通常のDebian/OpenSSHのデフォルト設定だけで初回無認証rootアクセスが成立するとは仮定しない。具体的な安全な実装と無認証停止手順は別PRで実装・検証する。

## 受入ゲートと安全境界

- Codexまたは人間のRunbookに基づく手作業で、P25/P44ペアの導入を再現できる。P44空判定・既存データ保護・中断後の現物確認と復旧が可能である。専用のインストーラは受入条件にしない。
- P25とP44マニフェスト・カーネルモジュールABI・SHAを独立検証する。
- P44初回起動後のLAN実通信、隔離初回無認証SSH、端末固有のホスト鍵永続化、rootパスワード/公開鍵の保存、個別認証での再接続、無認証ログイン停止を独立試験する。
- P44が空/破損の場合、安易な初期無認証サービスが起動しないことを検証する。
- 署名済みP25の一般配布可否は、LKの署名要件・再配布権限を別途確認する。一般ユーザーが署名済みP25を入手できると断定しない。
- **この決定は署名、実機書込み、P44変更、slot切替、再起動、公開配布の実行承認を含まない。** 実装PRでソース変更・ホスト側テストを進めても、実機操作には別途必要な承認を得る。

## Codexへの調整指示

既存の[PR #25](https://github.com/Karin-Laboratory/Debian13-Terminal6/pull/25)等は本憲章v1.3を優先し、旧「P44空→initramfs無認証TCP/22→ZIP展開」は完成条件から外す。P25のLANと**認証付き**救援（TCP/2222など）は別の故障回復機能として維持可能。P44側の初期無認証SSHは別の実装課題とするが、**外部P44導入ツールの新規開発は禁止**。既存のRunbookを利用し、Codexまたは人間が安全確認・書込み・展開・読戻しを行う。
