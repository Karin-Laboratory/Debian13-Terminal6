決定日：2026-11-18 / 状態：**採用決定・実装／実機受入は未完了**  
正本：[P25安定基礎設計憲章 §6](../P25-FOUNDATION-POLICY.ja.md)
導入順序の後続決定：[方式B（外部事前導入）](CUNIT-EXTERNAL-P44-INSTALL-METHOD-B-20261118.ja.md)

## 決定

ユーザーがダウンロードした共通P25と、初期状態では**中身が空のP44**から導入する初期認証方式を、**OpenWrt型の初回無認証SSH（案D）**とする。**インストール順序は後続の方式B決定により変更済み：起動前に外部環境からP44へDebianを展開する。** [方式B決定記録](CUNIT-EXTERNAL-P44-INSTALL-METHOD-B-20261118.ja.md)参照。

最初は物理的に隔離された有線ケーブル直結で、C号機の `lan2`・`lan3` を束ねた `br-lan` の初期管理IP `192.168.1.1/24` へ、**接続元に鍵を設定しなくても** `ssh root@192.168.1.1` で接続できるようにする。初期状態のTCP/22はroot無認証のプロビジョニング専用サービスであり、インターネットや家庭内LANには露出しない。

- **方式Bが現行正本。** インストール前の空P44に対して無認証SSHを提供しない。純正B/復旧環境から先にP44へDebianを展開する。**初回ログイン先はP44に導入済みのDebian上の初期設定用SSH**。P25/initramfsはZIP導入インストーラではない。
- Debian rootfsをP44へ展開したあと、利用者が `passwd root` で**Debian側**のパスワードを設定するか、`/root/.ssh/authorized_keys` に自分の公開鍵を登録する。
- 初期設定が永続化・再接続検証されたら、無認証SSHを自動的に停止。パスワードでも鍵でもよいが、**ユーザー公開鍵だけ設定した場合に空パスワードログインを残さない**。
- 初回ホスト鍵は各実機で新規生成し、秘密鍵をP44の永続状態に保存して再利用する。公開P25には配布者の秘密鍵・共有パスワード・認証済みユーザー鍵を含めない。ホスト鍵の指紋をUART等で独立確認できるようにする。
- 初期設定完了後はP44 Debianの通常SSH/TCP22で個別認証。別ポートの救援SSH/TCP2222は独立した認証方式で保護し、故障を口実に初回無認証rootを復活させない。

## 理由・比較

当初のA（UARTでDebian netinst型設定）とB（PCで事前設定ファイル作成）は、物理UART操作やファイル搬入の準備が必要。初期導入時は利用者の手元に実機と隔離ケーブルがあるため、ユーザーは接続元鍵を配布物へ個別注入する仕組みより、OpenWrtの簡単な初回接続を優先した。C（共通初期パスワード）は広く既知の認証秘密に依存し、E（ワンタイムパスワード）はUARTや表示経路を要する。今回の選択により**初回LANの物理アクセス権を所有者確認の代用**とすることを明示的に承認したが、認証が不要なrootを公開するリスクは消えない。

## 解決が必要な実装ゲート

1. **P44空の判定**：本当に空のext4なのか、既存Debian/データの保護対象なのかを検出。判定が曖昧ならデータを変更せず停止する。
2. **Debian P44側の初回無認証SSH**：Debian展開・起動後だけTCP/22、`192.168.1.1/24`、`br-lan`（構成要素は `lan2` と `lan3` だけ）で受け、それ以外のネットワークでは受けない。使用するSSHサーバーの設定は動作・版ごとにテストし、一般的なsshdのデフォルトで実現すると仮定しない。P44が空/不正ならfail-closed。
3. **外部事前導入方法（方式B、専用ツールなし）**：起動前に純正B/復旧環境からCodexまたは人間が既存Linuxコマンドを実行する。正確なPARTNAMEとP44空判定を検証し、個別承認後に署名済みP25を`boot_a`へ`dd`等で書込み、`P44-install.zip`内のrootfs tar/対応モジュールをP44 ext4へ適切な属性を保って配置する。途中停電後は作業状態を再確認し、保全・整合性・SHA読戻しを手順書に従って実施する。P25/initramfsからZIP展開せず、専用導入ツールも作らない。
4. **ホスト鍵**：初回生成とP44上の耐久性ある保管、通常/救援サービスへの引継ぎ、指紋確認、再起動後の鍵一致。
5. **認証移行**：パスワード設定・鍵登録の両方で、P44へ保存・権限/内容の検査、別セッションでの個別認証、無認証TCP22停止と再起動後の再有効化防止。管理不能にならない復旧経路を保持。
6. **隔離・警告**：このモードでは「同じ有線L2から先に入った誰でもrootになれる」。利用者に**隔離直結（原則PCを1台接続・反対端子は抜線）**を明示。2026-11-22の所有者改定により `lan2`・`lan3` 間のローカル管理ブリッジ `br-lan` のみ例外として許可し、外部へのブリッジ、WAN、Wi-Fi、家庭LANへの接続、DHCPサーバー・NAT・IP転送の初期自動起動は禁止。両端子を同時利用する場合、どちらからも初期無認証rootへ接続可能であり、全接続先を信頼・隔離しなければならない。家庭LAN `192.168.0.0/22` と初期 `192.168.1.0/24` は重複する。
7. **実機受入**：外部環境でのP25/P44ペア導入・P44読戻し、Debian起動、UART、ARP、Debian上の初回SSH無認証、`passwd root`または公開鍵登録、認証済み再接続、無認証再ログイン拒否、再起動、電源断復帰、P44故障時の認証付き救援手順を別々に実測。
8. **署名・バージョン**：既存PR #25の公開鍵必須・鍵なしfail-closedイメージは**旧仕様**であり、決定を反映する新しいP25ではない。改修後に実製造・独立SHA検証・非公開保存、正確なSHAへの署名承認と実機投入承認を別途得る。

## 禁止事項／本決定によって許可されないもの

この文書は**所有者の設計判断**を記録するもので、現在稼働中の純正slot B、C号機P25/P26/P44/GPT、bootcontrol、署名鍵に対する操作承認ではない。Codexはこの記録を理由として機体を再起動・書込み・署名・RF送信しない。既存の実験PRのgreen CIを新方式の受入PASSに転用しない。


## 2026-11-22 所有者による有線2ポート初期仕様の改定

- Debian P44の標準初期管理LANは、MediaTek MT7531 DSA `lan2` / `lan3` のブリッジ `br-lan` とし、`192.168.1.1/24` をブリッジにだけ設定する。2つの物理ポートへ個別に重複するIPアドレスを割り当てない。
- DHCPサーバー、NAT、IP転送、WANルーティングは初期無効。WAN/LAN分離はユーザーによる初回認証設定後の通常運用変更とする。
- これまでの「初回無認証期間はブリッジ全般禁止」は**`lan2`・`lan3` 間の隔離管理ブリッジのみ例外**とする。ただし、ブリッジで接続できる全ての相手が無認証rootアクセス可能なため、未使用端子は抜線し、家庭内LAN・インターネット・未信頼スイッチへ接続しない。ユーザー向け配布手順でこの危険を明示する。
- 個人の公開鍵・パスワード・端末生成SSHホスト秘密鍵・端末固有MAC等を一般配布のP25/P44に含めない。初回は利用者自身が認証情報を設定し、独立した再接続試験後、無認証SSHを**両ポートから**恒久停止する。認証方式のほかの条件は従来どおり。
- 受入ゲート：P44実機で `br-lan` のIPと `lan2` / `lan3` の参加・各1Gbpsリンク・各端子からの `192.168.1.1:22` 到達を確認する。初回無認証SSHの隔離条件、認証移行、他ネットワークへ橋渡ししていないこと、P44設定の起動後永続性は別々に受入試験する。
- C号機Debian 13.8、`6.18.63-debian-t6-proto2` の**稼働中**実機では、P25を変えずに `systemd-networkd` の `br-lan` と2ポート各1Gbps/SSHを確認（2026-11-22、所有者ログ）。ただし**再起動後は未試験**で、これ自体は一般配布ZIPの再製造や他個体への適用確認を意味しない。
- 本設計改定は配布仕様と受入方針の変更であり、P25/P44の新規書込み、署名、起動slot変更、再起動、RF操作の許可ではない。
