# C号機 Debian 13 ESP32-C3 UART1の実測

2026-11-14。P44書込み・APT・再起動後の限定的な復帰試験がPASSした後に実施。

- `/dev/ttyS1`はMediaTek UART `0x11003000`（IRQ181、ST16650V2）へ対応。純正OS資料の`esp32_uart`/`esp32_controllerd`起動記録と整合。
- Debian上でttyS1を使用中のFD/プロセスは見つからなかった。試験前のUART1 TX/RXカウンタは0/0。GPIO106/382、電源・reset信号の実配線や制御極性は今回未確認。
- `tools/esp32-at-probe.py`をRAM上で実行。115200 8N1、hardware flow controlなし、TIOCEXCLで単一open。`AT`にOK、`AT+GMR`に版情報の応答を得た。TX/RXカウンタは12/195へ進んだ。
- 応答の版はESP32-C3向けESP-AT `3.1.0.0-dev`、SDK `v5.0-541`系。完全なbuild provenanceやchip identityは別途確認が必要。
- probeは元のtermios設定を復元し、ファイルは`/run`にのみ置いた。RF送信試験、BLE gateway API、Linux HCI対応、firmware書換え、reset/GPIO操作は未実施。

評価：**DebianからESP32-C3のAT UART通信と版照会は実機PASS**。Wi-Fi/BLE機能そのものの利用可否は未検証。次は純正`esp32_controllerd`のコマンド契約とGPIO power/resetのソース根拠を調べ、必要な読み取り専用状態を取る。

他の安全な列挙：MT7996 0x7990/0x7991はPCI列挙、`phy0`登録。Wi-Fi MCU message timeoutを1件観測したため無線通信PASSではない。CCCI device node群、`/dev/hwrng`、ttyS0/S1/S2は存在する。一方、I2C adapterとPWM chipのsysfs classは未生成。GNSS/BT/CCCIの実機能は今回試験していない。
