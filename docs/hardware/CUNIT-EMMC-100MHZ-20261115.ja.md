# C号機 eMMC 100MHz化候補と実機試験ゲート

更新日: 2026-11-15 JST

## 状態

この記録は実機の読み取り専用事前調査と、署名済み候補のホスト側検証を区別する。安全な復旧起動経路を実証できていないため、候補を実機へ適用せず、書込み耐久試験と再起動試験も開始していない。

| 項目 | 実測・判定 |
|---|---|
| 現行カーネル | Debian 13、Linux 6.18.63系 |
| CQE | 稼働DTで `supports-cqe` 不在、sysfs `cmdq_en=0` |
| 現行クロック | DT `max-frequency=200000000`、debugfs ios実クロック約190MHz |
| 現行転送モード | HS400、8-bit、1.8V |
| 現行MMCエラーカウンタ | 採取時は全て0。過去のDATA TIMEOUT/CQE recovery/ext4 I/O errorを否定しない |
| 100MHz候補 | DTBの意味差分はmax-frequencyのみ。no-CQEとHS400関連設定を維持。既存カーネルを再利用 |
| P25署名 | 保護された署名手順と独立RSA-PSS検証に成功。候補P25は未インストール、実機起動未検証 |
| P44バックアップ | 保存済みrootfsおよび補助アーカイブのハッシュ/アーカイブ検査に成功。復元起動試験は未実施 |
| 書込み試験 | 16–256MiBの15ケース、および再起動永続性試験とも未実施 |

## 安全ゲート

boot_aを書き換える前提として、slot B経由で元の起動へ戻せることが必要である。現在の `terminal6-bootctl` は状態表示等のみ対応し、slot選択操作を「LK transition semantics not yet proven」として拒否する。slot Bの領域にはLinux 5.4.238の文字列があるが、現物イメージは保管済み参照イメージと一致せず、現在のP38/P39からの起動・slot A復帰も実証されていない。boot制御フラグの表示だけでは次回起動先を保証できない。

このため、boot_a/P25、boot制御領域、P44への書込み、fsck、再起動を行っていない。UARTは接続確認のみで、端末側リセットやGPIO操作は行っていない。

## 次の実施条件

1. 現在のslot Bイメージと起動選択機構を特定し、可逆なslot B起動方法を根拠とともに確立する。
2. slot B起動後にslot Aへ確実に戻れる手順を、別の安全な検証サイクルで確認する。
3. その後、署名済み100MHz P25を適用し、readback・起動後の実クロックが100MHz以下であることを確認する。
4. 100MHz以下、cmdq_en=0、HS400状態、P44正常マウント、管理経路復帰、新規エラーなしを確認してから、指定の段階試験を開始する。
5. 異常時は試験を停止し、修復目的のfsckや再試行を行わず、ログを保全する。

## 評価上の制限

署名検証成功は、P25の実機受理・起動や100MHz動作の証明ではない。バックアップアーカイブ検査成功は復元可能性・起動成功の証明ではない。今回の負荷での安定性評価および長期安定性の結論は、実機試験完了後に別途記録する。
