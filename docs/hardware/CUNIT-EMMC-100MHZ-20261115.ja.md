# C号機 eMMC 100MHz化候補と実機試験

更新日: 2026-11-15 JST

## 現状

2026-11-15の読み取り専用事前調査では、C号機はDebian 13 / Linux 6.18.63系、no-CQE、HS400、8-bit、1.8Vで稼働し、debugfs iosの実クロックは約190MHzだった。稼働DTに `supports-cqe` はなく、sysfsの `cmdq_en=0`。採取時のMMCエラーカウンタは0だったが、過去のDATA TIMEOUT/CQE recovery/ext4 I/O errorを否定するものではない。

no-CQEを維持し、DTの `max-frequency` だけを100MHzにした候補を作成した。既存カーネルを再利用し、HS400・bus-width・電圧等は保持した。P25は保護された署名手順と独立RSA-PSS検証に成功したが、まだC号機に適用していない。100MHz動作も実機未確認である。

## 復旧経路の照合

以前の本記録では、`terminal6-bootctl` がslot選択を拒否したこととP38ハッシュ不一致を理由に、slot B復旧経路が未確認と扱っていた。この判断を訂正する。

非公開 [SBAT6A-Offline-Archive PR #157](https://github.com/Karin-Laboratory/SBAT6A-Offline-Archive/pull/157) の2026-11-14 C号機実機記録では、次を実施し成功している。

1. C号機の純正rootfs Bをread-only chrootで使い、純正 `quec_bootctrl -F` によりB起動を選択。
2. C号機がLinux 5.4.238で起動し、過去のhost keyを用いたstrict SSH接続を確認。
3. 純正 `quec_bootctrl -s` でA起動へ戻し、Debian 13 / Linux 6.18.63、P44 ext4、管理LANとSSHの復帰を確認。

記録では試験中にP26、P44、stock B、GPT、OEM領域を変更していない。従って、`terminal6-bootctl` の拒否は、別の純正ツールによる同一C号機の成功実績を取り消すものではない。

## P38ハッシュの出所

2026-11-15 00:34 JST採取の現行C号機P38は `/dev/mmcblk1p38` / PARTNAME `boot_b`、32MiB、Linux 5.4.238だった。比較に使ったP38 SHA `82873700…` は、2026-10-21のSBAT6A **B号機** (`SBA6D`) の `/dev/mmcblk1p38` から取得された記録で、別個体の値だった。したがってハッシュ不一致は誤った個体参照によるものであり、C号機P38の内容変化を示す証拠ではない。

PR #157の公開可能な結果には、C号機slot Bを未変更とした記録と実起動成功があるが、同一C号機P38の試験前全量SHAは記載されていない。現状の判断は「同一C号機に対するB起動/A復帰手順の実績あり」であり、P38全量SHAの時系列一致までは主張しない。

## 実機試験の状態と次の工程

100MHz候補の実機適用、boot_a書換え、P1 slot切替、再起動、P44書込み試験はまだ行っていない。P44バックアップの検査は成功しているが、復元起動試験とは区別する。

このターンでのraspi4 SSH再接続はタイムアウトしたため、新たな実機操作は実施できなかった。管理経路が利用可能になり次第、PR #157の実証済み純正 `quec_bootctrl` 手順でslot Bからの起動とA復帰を確保し、既存の署名済み100MHz候補を適用する。その後、実クロックが100MHz以下であること、HS400/no-CQE、管理経路、P44正常マウント、新規エラーなしを確認してから指定の段階試験を開始する。

1. 16/32/64/128/256MiBを各3回、個別に書込み・direct read・SHA256比較。
2. 15回すべて成功した場合に限り、256MiB検証ファイルを保持して通常再起動し、読戻しと整合性を確認。
3. 異常があれば直ちに停止し、修復目的のfsckや再試行は行わない。

署名検証や過去のslot切替成功は、100MHz候補の実機起動・今回の書込み耐久試験・長期安定性を証明しない。
