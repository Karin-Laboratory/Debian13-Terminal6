目的は、物理LAN 2口が使え、インストールする人がSSH鍵を準備せずに初回設定できること。既存の12文字の一時パスワード案および鍵登録必須案は、現在の受入条件ではない。過去のCI結果は旧案の検査であり、新案の合格とは扱わない。

## 有線LAN

- 各物理ジャックを同じ対向機・同じケーブルで一口ずつ試験し、ジャックとLinuxインターフェースの対応、両端のリンク速度、ARP、双方向ping、SSH接続を別々に記録する。片方向の受信カウンターやFDB学習は、IP疎通や物理送出の証明にしない。
- 未使用の試験IPと隔離を確認する。障害時は、同じ試験窓でブリッジ送信、CPUポート、物理ポート、対向機の受信を区別する。スイッチのカウンターとLinuxのカウンターは測定点が異なる。ブリッジ定義や起動イメージを同時に変えず、一つの差分で比較する。
- 対向機はホスト名だけで判断せず、型番・ポート仕様と接続時の実測を確認する。同じIPを既に使っている機器がある場合、同じL2へ接続しない。片端だけのIP情報では対向を特定しない。
- 双方向の通信試験では、100 Mbps/fullの対向と1 Gbps/full対応の対向を別の試験ケースにする。100 Mbpsまでの対向では100/fullのリンクを正常とし、1 Gbpsの判定は未試験とする。1 Gbps対応側でもリンク値だけでは合格にしない。内部CPUポートの固定リンク速度と外部ジャックの交渉速度は別々に記録する。
- 起動時の管理処理は、対向の速度やケーブルの未接続だけでLAN全体の故障と判定しない。起動処理の判定とARP・双方向pingの合否を分け、100/full、1 Gbps/full、未接続での状態を比較する。古い速度条件だけを解除して、未検証のハードウェア操作を実行する構成は候補にしない。
- 再起動後も、両口の疎通と設定持続を確認する。

### 旧ビルドの停止と回帰確認

実機の当該起動では実効 unit に drop-in がなく、3 モジュールのロード成功後に管理サービスが約4秒で終了コード1を返した。停止箇所のログはなく、旧スクリプトの 1000 Mbps 固定条件は候補の一つであって、双方向通信不成立の原因を確定したわけではない。

- 候補ビルドでは管理サービスの終了結果と、各ポートのリンク観測をそれぞれ記録する。100 Mbps/full とケーブル未接続を 1 Gbps 未達だけで障害扱いしない。旧レジスタ初期化が速度条件の緩和で起動しないことも確認する。
- 比較時は起動単位を識別し、実効 unit、上書き設定の有無、実行されたスクリプト、終了結果、同じ起動の journal を採取する。管理サービスが成功しても、別途 ARP と双方向 ping が通るまでは LAN 合格としない。

## SSH 初回設定

- 新規インストール、既定では初回セットアップ待受なし。隔離直結と現地での明示操作がそろったときのみ、短時間のセットアップを開始する。家庭LAN、Wi-Fi、別ポートからは受付不可。直結を確認できない場合は開かない。
- 利用者は事前のクライアント鍵を必要とせず、初回SSHで自分のrootパスワードを設定・確認する。一般ユーザーは自動作成しない。共通の初期パスワードは配布しない。設定が終わるまで通常のrootシェルや転送を提供しない。
- 設定確定後は初回受付を閉じ、管理LANに限定した通常SSHで登録済みパスワードを使う。SSHのサーバー側ホスト鍵は個体ごとに生成し、初回・再接続の両方で相手の機器を識別できるようにする。
- 不一致・空入力・途中切断・タイムアウト・再起動・同時接続を試験する。失敗や中断で通常シェルに遷移しないこと、成功後に初回設定が再開しないこと、パスワードがログや成果物に残らないことを確認する。

[Armbian の初回起動ガイド](https://docs.armbian.com/getting-started/first-boot-and-login/)の、最初にrootパスワードを決める流れを参考にする。固定の出荷時パスワードと一般ユーザー作成は採用しない。本文は受入条件のみで、コード・起動設定・実機に変更を加えるものではない。
