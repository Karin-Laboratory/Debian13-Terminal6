# C号機 320MHz 電波暗室試験モード設計方針

作成日: 2026-11-16  
状態: **方針提案 / 未実装 / 320MHz RF送信未承認・未実施**

## 決定する方針

Debian 13 / Linux 6.18.63 / MT7990 (mt76/mt7996) では、将来的に **320MHzのドライバ対応を保持・開発**する。320MHzを恒久的にソースから排除しない。一方、一般向けのデフォルトは **6GHz EHT 160MHz以下**とし、320MHzのcapability広告・320MHz送信設定を無効にする。

ユーザーがSSHで **電波暗室試験モード** を明示的に選択した場合のみ、試験専用ドライバの320MHz capabilityを利用できる設計にする。ただし **SSHで「暗室内」を宣言しただけでは、法的な送信許可も設備の適合性も証明されない**。モード選択（能力の解放）と実際のRF送信開始は別段階とする。

これは[PR #6](https://github.com/Karin-Laboratory/Debian13-Terminal6/pull/6)で実機確認された「160MHzを保持・320MHz非広告」の成果を後退させない将来方針である。MLOの[PR #10](https://github.com/Karin-Laboratory/Debian13-Terminal6/pull/10)とも整合させる。

## モードの想定仕様

| 項目 | `normal`（通常運用） | `chamber`（電波暗室試験） |
| --- | --- | --- |
| デフォルト | **常にこちら** | 明示的なSSH管理操作でのみ選択 |
| 320MHz EHT capability | 広告しない | 専用ビルド・ドライバで有効化可能 |
| 80/160MHz capability | 従来どおり保持 | 従来どおり保持 |
| 320MHz RF送信 | 禁止 | **独立した安全・法令ゲートを通過するまで禁止** |
| 再起動・異常終了 | `normal`を選択 | 持続しない。手動で再選択 |
| 不明・検証失敗 | fail-closed | `normal`へ復帰し送信停止 |

※「160MHz capabilityを広告できる」と「国内で160MHz送信してよい」は別問題。6GHz送信はどちらのモードでも別途、当該周波数・出力・技適／法令条件の検証を要する。

### SSH操作の将来インターフェース案（**コマンドは現時点で存在しない**）

```sh
sudo terminal6-radio-mode status
sudo terminal6-radio-mode chamber   # 320MHz capabilityの試験用構成を選択。送信は始めない
sudo reboot                         # 起動後、候補ドライバとiw phyを検証
sudo terminal6-radio-mode normal    # 通常運用へ戻す
sudo reboot
```

- root権限でのみ切替できること。通常モードは再起動時に自動選択されること。
- `chamber`は**320MHz対応をロード可能にする操作**であり、AP起動・ビーコン送出・320MHz RF試験の開始コマンドではない。
- 実送信の開始は独立した明示操作とし、開始時と送信中の継続的な安全条件評価が必要。別のコマンド仕様はゲート設計が固まってから決める。
- 設定状態、ロードしたモジュールのSHA-256、`iw phy`の広告内容、RF送信ゲートの状態、失敗理由を`status`に表示する。秘密情報・個体校正データは出さない。

## 実装方針

1. **既存OSSを優先する**。mt76/mt7996、mac80211、cfg80211、hostapdの320MHz EHT実装を再利用し、不足するMT7990固有差分のみ追加。capability bitだけでなく320MHz MCS/NSS・PHY/MU項目の整合性とデータパスも検証する。
2. **同一ソース系列から2モードを再現ビルド**。既存[PR #6 の160MHz/no320パッチ](https://github.com/Karin-Laboratory/Debian13-Terminal6/blob/codex/cunit-wifi7-mlo-audit-20261114/patches/0002-mt7996-cunit-6ghz-cap-160mhz-no320.patch)を通常版の基準とし、試験版の差分と各モジュールSHA-256を記録。既存の`terminal6-wifi-phy.service`でハッシュ検証してからロードする。
3. **切替時は無線停止→検証済みモジュール選択→再起動→読み戻し**。有線LAN・SSH・UART・stock slot B復旧経路を維持し、失敗したときは320MHz非広告の通常版へ戻す。P25署名や危険なフラッシュをモード切替の必須操作にしない設計を優先する。
4. **規制DBや送信制限は迂回しない**。`regulatory.db`の署名検証・周波数制限・地域設定・出力制限の無効化、実機固有校正の捏造・公開はしない。6GHz regdbの署名不一致は[PR #6](https://github.com/Karin-Laboratory/Debian13-Terminal6/pull/6)の未解決課題として別管理する。
5. **制御だけでは暗室を検証できない**。試験に使用する設備と測定根拠が準備できない間は、SSHで`chamber`を選んでも320MHz RF送信は開始できない。可能な範囲で外部インターロック（遮蔽扉等）と独立停止手段を連動し、扉の開放・状態不明・プロセス故障・条件喪失時は送信を止める。外部設備の構成によっては自動確認できないため、その場合は試験運用を許可しない。

## 法令・設備条件を確認するゲート

- C号機の個体銘板と技適番号・認証条件は未突合。調査中のA775 / 020-240075の6GHz記録は160MHzまでで、**320MHzの認証根拠として扱わない**。
- **適切な試験設備の内部で行い、適用される電波法上の条件に合致すること**を実測・文書で確認する。一般の部屋や単に扉を閉じた箱を「電波暗室」と称するだけでは不可。
- 免許不要の試験設備内微弱無線局の扱いを検討する場合、総務省告示による試験設備要件、電波法施行規則第6条第1項第1号の漏えい電界強度、ARIB TR-G1の直接法／間接法による測定を照合する。条件を満たさなければ、適切な実験試験局免許等の手続の確認が必要。
- **試験設備の条件を満たすことと、実装が正しく320MHz通信できることは別の判定**。どちらも独立して確認する。各条件が未確定ならRF試験は行わない。

資料:
- [e-Gov 電波法施行規則 第6条](https://laws.e-gov.go.jp/law/325M50080000014)
- [ARIB TR-G1: 電波暗室等の試験設備内の微弱無線局の電界強度測定方法](https://www.arib.or.jp/kikaku/kikaku_general/desc/tr-g1.html)
- [総務省 技術基準適合証明等を受けた機器の検索](https://www.tele.soumu.go.jp/j/sys/equ/tech/)

## 受入条件（未完了）

- [ ] ソースから通常版・試験版の両方を独立再現ビルドし、入力・SHA-256を公開可能な範囲で証拠化。
- [ ] `normal`で320MHz広告がなく160MHzが維持され、再起動・障害・不明設定時も`normal`となること。
- [ ] `chamber`の明示切替後のみ320MHz capabilityが現れ、**その操作だけではRF送信しない**こと。
- [ ] 送信許可ゲートが未成立／失効した場合の確実な送信禁止・停止を試験し、SSH切断、扉開放、サービス障害、電源再投入を含めて確認すること。
- [ ] `iw phy`、ドライバ実測、hostapd、対向端末で320MHz実通信・再接続まで試験すること。ただし実電波は適法な設備・手続を証拠化してから。
- [ ] A号機の観測値との読み取り専用比較を実施。A号機の独自regdb・校正データをC号機へ流用しないこと。
- [ ] UART/有線管理・既存の復旧スロットを維持し、通常モードへ確実に復帰できること。

**本PRは方針の文書化のみ。** 新しいSSHコマンド・320MHz試験版ドライバ・320MHz送信機能を実装または有効化するものではない。機器への書込み・送信も行わない。
